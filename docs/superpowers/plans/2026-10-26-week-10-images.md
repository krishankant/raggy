# Week 10: Images — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the facts inside pictures searchable. Standalone image files, and figures inside PDFs, slides and Word files, become text through OCR (week 9's engine) and, optionally, a vision model's description. Each image is cited by file and page. Optional CLIP embeddings add text-to-image and image-to-image search. Every mode is measured on a suite whose answers exist only in images.

**Architecture:** An `ImageReader` turns image bytes into one text block, `[Image: <label>]` followed by a description and/or `Text in image: …`. It caches results in SQLite, keyed by image hash + mode + model + prompt version. Loaders reach it through `LoadOptions.read_image`, a callable that isn't part of any key, so they stay pure functions of (bytes, options). The settings it depends on (`images`, `vision_model`, `VISION_VERSION`) go in `pipeline_key` and the eval key. The vision call goes through the existing `LLM` interface, extended with `images=`. CLIP vectors live in a second LanceDB table, `images`, written during ingest only when `RAGGY_IMAGE_SEARCH=on`.

**Tech Stack:**
- No new runtime dependencies. Pillow (already pulled in by pdfplumber) handles decoding and resizing, and rapidocr provides OCR (week 9).
- Vision: Ollama `qwen3.5:4b` (vision capability verified with `ollama show`; 16.7 s per image warm on this M2, 82 s cold), OpenAI `gpt-5.5` (10.8 s; 357 prompt tokens for a 640×400 chart), or Claude through the Anthropic adapter.
- CLIP: fastembed `Qdrant/clip-ViT-B-32-vision` and `Qdrant/clip-ViT-B-32-text`, 512 dimensions, 0.34 GB, MIT. Both listed by fastembed 0.9.0 before planning.

**Spec:** `docs/superpowers/specs/2026-10-23-raggy-course-design.md` (section 7, week 10 row; section 9: heavy local models need a small default and a configurable larger size, and everything runs on an Apple Silicon Mac with no GPU)

**Branching:** `dev/week-10` from `dev/week-09`, in worktree `raggy-week10`. It's rebased onto main after weeks 7–9 are released. Eval runs use `RAGGY_INDEX_DIR=<this worktree>/.raggy`, never a folder shared with another worktree (observation 35).

## Global Constraints

- `uv run pytest` passes offline. Tests use a fake vision LLM and a fake CLIP; no model downloads.
- `RAGGY_IMAGES`: `off | ocr | vision`, default `off` until measured.
  - `off` is week 9's behaviour: image files are skipped with a warning naming the switch, and figures are ignored.
  - `ocr` writes `Text in image: …`.
  - `vision` writes a description, plus the OCR text when OCR finds any.
- `RAGGY_VISION`: `ollama | openai | anthropic`, defaulting to `RAGGY_LLM`. `RAGGY_VISION_MODEL` defaults to `qwen3.5:4b` for ollama and `claude-opus-5-5` for anthropic, and is required for openai.
- `VISION_VERSION = "vis-v1"`. The prompt asks for: what kind of image it is, its title, every label and number exactly, what is shown (objects, colours, arrows and connections), plain text, under 150 words.
- Images are decoded with Pillow, converted to RGB (palette, CMYK and alpha images included; GIF uses its first frame) and resized so the long edge is at most 1,568 px. They're sent as PNG.
- Images under 100 px on their short side are decorative and skipped. So is an image whose bytes repeat more than twice in one document (a logo on every slide): it's read once, at its first occurrence.
- A scanned PDF page is OCR'd whole (week 9). Its figures aren't extracted separately.
- Vector-drawn charts in PDFs (no raster image) and `<img>` in HTML are out of scope. The lesson names both.
- The cache lives at `index_dir/vision-cache.sqlite` and is added to `CACHE_FILES`. Failed reads aren't cached.
- **Decision rules, set before any run (observation 31):**
  - **`images=ocr`** becomes the default over `off` if `images` recall@4 rises, the fictional, fictional-web, manual and rich suites stay identical (none of them contains a raster image), and OCR costs under 2 s an image.
  - **`images=vision`** becomes the default over `ocr` only if `images` answer correctness rises by at least 0.05 (one question in 20) *with the local default model*, and warm description time is at most 30 s an image on this M2. Descriptions are made once at ingest and cached, so this is a one-off cost per image. The hosted model is measured too, and reported as the accuracy ceiling.
  - **CLIP image search** is on by default only if, on the `images` questions, text-to-image recall@1 (the gold image ranked first among all images) beats text search over the image blocks by at least 0.05.
  - Held constant: chunking, retrieval (week 6/7 defaults), top_k, the answer model (gpt-5.5) and the judge (gpt-5.4).
- (Observation 33) The data can tell the modes apart. Questions are tagged:
  - `text-in-image`: OCR should be enough.
  - `association`: OCR reads the parts but loses which value belongs to which label (charts, diagrams).
  - `visual`: no text at all (colour, shape, count). Only vision can answer these.
- Never move the week-01..09 branches or tags. Cut `week-10` from a verified SHA (observation 34).

## Review Focus

1. **Corrupt or unsupported image bytes** (a truncated JPEG, an SVG renamed `.png`): the image file raises one `LoadError` naming the file. A figure inside a PDF or slide is skipped with a warning, and the rest of the document still loads. Test: `test_corrupt_figure_skipped_document_loads`.
2. **The vision call fails** (Ollama down, a 429, an empty reply): the block falls back to the OCR text, the failure is counted in `ImageReader.failures` and reported by ingest and eval (week 7's rule: a fallback must never pass for a result), and nothing is cached. Test: `test_vision_failure_falls_back_to_ocr_and_counts`.
3. **Odd pixel formats and sizes** (a palette PNG with transparency, a CMYK JPEG, an animated GIF, a 6,000 px photo) are normalised before OCR and vision. Test: `test_prepare_image_normalises_modes_and_size`.
4. **The same logo on every slide**: it's read once, and its block appears once. Test: `test_repeated_image_read_once`.
5. **Cache paths** (observation 29): the vision cache path derives from `index_dir`, which already resolves blank to the default. The cache file is listed in `CACHE_FILES`, so a stale-index rebuild keeps it. Nothing new deletes a path.

**Files:**
- Create `raggy/ingest/images.py`.
- Modify `raggy/generate/openai_llm.py`, `raggy/generate/anthropic_llm.py`, `raggy/generate/fake.py`, `raggy/generate/llm.py` (protocol), `raggy/config.py`, `raggy/pipeline.py` (`pipeline_key`, `Raggy.load_options()`, the ingest report) and `raggy/evals/runner.py` (eval key, `CACHE_FILES`, `raggy.load_options()`).
- Test `tests/week10/test_images.py`.

**Interfaces (Produces):**
- `LLM.complete(system, user, cache_prefix=None, images=None)`. `images` is `list[bytes]` of PNGs. OpenAI and Ollama send `image_url` data URIs; Anthropic sends `{"type": "image", "source": {"type": "base64", "media_type": "image/png", ...}}`. `FakeLLM` records the image count.
- `prepare_image(data: bytes) -> tuple[bytes, int, int] | None`: PNG bytes, width and height after normalising. Returns `None` for a decorative image (short side under 100 px). Raises `ImageError` on undecodable bytes.
- `ImageReader(mode, llm=None, cache_path=None)` with `.read(data: bytes, label: str) -> str | None` (the block, or `None` if decorative), plus `.failures`, `.calls` and `.cached`.
- `LoadOptions.read_image: Callable[[bytes, str], str | None] | None = None` (`compare=False`, `hash=False`).
- `Config`: `images`, `vision_provider` and `vision_model`. `Raggy.load_options()` binds an `ImageReader`.
