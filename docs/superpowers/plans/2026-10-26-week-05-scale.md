# Week 5: Scale — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** raggy handles tens of thousands of documents. Re-embedding is avoided with a content-keyed embedding cache, embedding gets faster by batching texts of similar length, the store moves to LanceDB (on-disk and incremental, with metadata filters, and ready for week 6's full-text index), and approximate (ANN) search is measured against exact search on a 57,638-document benchmark. ANN becomes the default only if the numbers say so.

**Architecture:** A `VectorStore` protocol has two implementations: `NumpyStore` (week 1, kept as the exact in-memory baseline) and `LanceStore` (new, the default). `CachedEmbedder` wraps any embedder and keeps vectors in SQLite, keyed by sha256(model + text), so a re-run only embeds text it has never seen. `Chunk.meta` carries document metadata (type, title, modified) into the store, so searches can filter on it. A new `fiqa` suite (BEIR FiQA-2018: 57,638 docs, 648 test queries) gives a scale where exact and ANN search differ. The eval records, per question, how much of the exact top-k the ANN top-k found.

**Tech Stack:** Adds `lancedb>=0.40` (Apache-2.0; pulls in `pylance` and `pyarrow`). Measured before planning, on this Mac (M2, 8 GB):

| measured | value |
| --- | --- |
| numpy exact search p50, 10k / 100k / 500k random 384-d vectors | 0.20 / 3.5 / 16 ms |
| LanceDB flat (exact) search p50, same sizes | 4.1 / 22 / 93 ms |
| LanceDB IVF_HNSW_SQ, default params, recall@10 vs exact (random vectors, the worst case) | 0.46 / 0.10 / 0.04 |
| fastembed bge-small throughput, 1,500-char texts: batch 64 / batch 16 / 4 worker processes | 9.2 / 11.7 / 1.5 texts/s |

**Spec:** `docs/superpowers/specs/2026-10-23-raggy-course-design.md` (section 7, week 5 row; section 9 "embedded store, no server")

## Global Constraints

- `uv run pytest` passes offline, with no keys and no downloads. LanceDB runs in a temp directory; the FiQA tests use a tiny BEIR fixture.
- No server-based vector DB. LanceDB is embedded and on disk.
- FiQA is downloaded on demand to `evals/data/` (gitignored) and never committed. URL `https://public.ukp.informatik.tu-darmstadt.de/thakur/BEIR/datasets/fiqa.zip`, sha256 `32c7df99ed21252fdfb2cf3f5673502a8d245ee0c44c4a133570d92ce2b3ad02`. Benchmark suites are never deduped.
- The store, the ANN settings and the embedding model are in the registry's settings key and the eval cache key. The embedding cache is keyed by model name and text, so it is never wrong across settings.
- Eval rebuilds keep the caches (`context-cache.sqlite`, `embed-cache.sqlite`). The ownership guard treats a folder that holds only caches as raggy's own.
- **Decision rule, set before any run (observations 31 and 33).** ANN is on by default only if, on FiQA, it keeps nDCG@10 within 0.005 of exact search **and** exact search's p95 retrieval latency is above 100 ms. Otherwise the default is exact search, with ANN as a switch. The comparison holds fixed: the same index, chunker and embedder, top-k, and machine. Latency is reported with the hardware named.
- The week 1–4 branches and tags are never moved. Cut `week-05` (branch and tag) at the end, then push (the owner asked for pushes when a week is done).

## Review Focus

1. **Re-ingest replaces, never duplicates.** LanceStore must delete a source's old rows before adding new ones, across batches and processes. Test: `test_lance_reingest_replaces_rows`.
2. **The quote in a filter value** (`--source "/docs/it's here"`) must be escaped, not injected into the SQL `where`. Test: `test_filter_values_are_escaped`.
3. **The embedding cache returns vectors in input order**, including duplicates within one call and a mix of hits and misses. Test: `test_cached_embedder_order_and_duplicates`.
4. **An index built with one embedder, then searched with another**, raises EmbedderMismatchError (LanceStore too). Test: `test_lance_embedder_mismatch`.
5. **An ANN index that is stale after new rows are added** must still return the new rows. LanceDB scans unindexed rows; the test pins it. Test: `test_ann_finds_rows_added_after_index`.
6. (Observation 29) The only deletes are row deletes by `source` (an exact match, escaped) and the eval rebuild behind the existing guard. Switching the store never deletes the old numpy files.

### Task 1: Embedding cache and length-sorted batching

**Files:** Create `raggy/embed/cache.py`. Modify `raggy/embed/fastembed_embedder.py`, `raggy/pipeline.py`, `raggy/config.py`, `raggy/evals/runner.py`, `raggy/cli.py`. Test `tests/week05/test_embed_cache.py`.

**Interfaces (Produces):**
- `EmbeddingCache(path)` (SQLite, table `vectors(key TEXT PRIMARY KEY, dim INT, vec BLOB)`) with `get_many(keys) -> dict[str, np.ndarray]`, `put_many(dict)` and `commit()`.
- `CachedEmbedder(inner: Embedder, cache: EmbeddingCache)` implements `Embedder`. `embed_documents` looks up `sha256(f"{inner.name}\0{text}")`, embeds only the misses (each distinct text once), stores them, and returns rows in input order. It counts `hits` and `misses`. `embed_query` is not cached, since queries are one-offs.
- `FastEmbedEmbedder.embed_documents` sorts its texts by length, embeds them with `batch_size=16`, and restores the input order.
- `Config.embed_cache: bool = True` (`RAGGY_EMBED_CACHE`). `Raggy.embedder` wraps the embedder in a `CachedEmbedder` at `index_dir/embed-cache.sqlite` when it's on. `IngestReport` gains `embedded` and `embed_cached`, and the CLI prints `embeddings: N computed, M from cache`.
- `runner.CACHE_FILES = {"context-cache.sqlite", "embed-cache.sqlite"}` is used by the rebuild and the guard.

### Task 2: The VectorStore protocol and LanceStore

**Files:** Create `raggy/store/base.py` and `raggy/store/lance_store.py`. Modify `raggy/store/numpy_store.py`, `raggy/types.py` (`Chunk.meta: dict = {}`), `raggy/pipeline.py`, `raggy/cli.py`, `raggy/config.py`, `pyproject.toml`. Test `tests/week05/test_lance_store.py`. Older tests that open `NumpyStore` files get `store="numpy"`.

**Interfaces (Produces):**
- `VectorStore` protocol: `embedder: str | None`, `__len__`, `add(chunks, vectors, embedder_name)`, `remove_source(source) -> int`, `search(query_vec, k, embedder_name, where: Filters | None = None, exact: bool = True) -> list[Hit]`, `sources() -> dict[str, int]`, `save()`. `make_store(config, create=True)` opens `numpy` or `lance`; with `create=False` it raises IndexNotFoundError when no index exists.
- `LanceStore(path)` keeps the table `chunks` under `index_dir/lance`. Columns: `id, source, text, idx, start, end, context, parent_start, parent_end, parent_text, doc_type, title, modified, vector`, with the `vector` length fixed by the first add. The embedder name is kept in `index_dir/lance/meta.json`. `add` deletes the incoming sources' rows, then appends. Scores: Lance's dot "distance" is `1 - dot`, so `score = 1 - _distance`. `save()` is a no-op, because Lance commits each write.
- `Filters(doc_type: str | None, source_prefix: str | None, modified_after: str | None)` has `.sql()`, with escaped values, and `.matches(chunk)` for numpy.
- `Config.store: str = "lance"` (`RAGGY_STORE`). The store is in `pipeline_key` and the eval cache key.
- `ingest_documents` copies `doc.metadata`'s `type`, `title` and `modified` into each chunk's `meta`.

### Task 4: ANN

**Files:** Modify `raggy/store/lance_store.py`, `raggy/config.py`, `raggy/pipeline.py`, `raggy/evals/runner.py`. Test `tests/week05/test_ann.py`.

**Interfaces (Produces):**
- `Config.ann: str = "off"` (`RAGGY_ANN`: off | on). `Config.ann_nprobes: int = 20` and `Config.ann_refine: int = 4` (`RAGGY_ANN_NPROBES`, `RAGGY_ANN_REFINE`). Lance only.
- `LanceStore.build_index(nprobes...)` uses `IvfHnswSq(distance_type="dot")`. Ingest builds the index when `ann == "on"` and there are at least 1,000 rows (an IVF index needs rows to train), and calls `optimize()` after each ingest so new rows join it. `search(exact=False)` uses the index with `nprobes` and `refine_factor`; `exact=True` uses `bypass_vector_index()`.
- Runner: when `ann == "on"`, each question also runs exact search and records `ann_overlap@k` (|ANN top-k ∩ exact top-k| / k) for k in the suite's ks. Retrieval latency is recorded for the ANN search.
