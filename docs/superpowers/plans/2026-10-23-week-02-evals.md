# Week 2: Evals Before Optimisation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `raggy eval --suite fictional|scifact` measures week 1's pipeline. Retrieval is scored with recall@k, MRR and nDCG. Answers are scored for correctness, faithfulness and citation precision by an LLM judge, plus refusal accuracy and latency. Each run is saved as JSON, and `raggy compare` shows the change between two runs. Committed baseline runs become the numbers every later week is measured against.

**Architecture:** A suite is a fixed corpus plus a question set. Gold evidence is stored as verbatim quotes, located in the corpus as character spans. A retrieved chunk counts as relevant when its span overlaps a gold span, so the gold labels survive any later change to chunking. The runner builds a cached per-suite index, then for each question it times retrieval and generation, scores retrieval with pure metric functions, and asks a judge LLM (behind the same `LLM` interface as week 1) for verdicts in JSON. SciFact is downloaded on demand and checksum-verified, and scored at document level so the numbers can be checked against published results.

**Tech Stack:** Same as week 1. No new dependencies. Downloads use `urllib` and `zipfile` from the standard library.

**Spec:** `docs/superpowers/specs/2026-10-23-raggy-course-design.md` (week 2 row, "Measured, not assumed")

## Review Focus

1. **A gold quote that isn't in the corpus** (typo, line wrap, a different apostrophe). Loading must fail and name the question id and the quote. A silent recall of 0 is not acceptable. Test: `test_resolve_gold_missing_quote_names_question`. Whitespace differences are tolerated: `test_resolve_gold_tolerates_whitespace`.
2. **The judge returns non-JSON, JSON inside a code fence, or an error.** Fenced JSON must parse. Garbage must give that question `judge.error`, be left out of the averages, and be counted in the report. The run must continue. Tests: `test_parse_json_in_fence`, `test_judge_garbage_records_error`.
3. **The answer model fails mid-run** (rate limit, Ollama stopped). That question records `error`, the run continues, and the report shows the error count. Test: `test_run_records_llm_error_and_continues`.
4. **A stale eval index after changing chunk size or embedding model.** The cache key covers the corpus fingerprint, the embedder name, the chunk size and the overlap. Any change forces a rebuild. Test: `test_prepare_index_rebuilds_when_settings_change`.
5. **A corrupt or partial SciFact download.** A checksum mismatch must raise with the URL and both hashes, and leave no half-extracted data that a later run would trust. Test: `test_download_rejects_bad_checksum`.

### Task 2: Eval data and retrieval metrics

**Files:**
- Create: `raggy/evals/__init__.py`, `raggy/evals/dataset.py`, `raggy/evals/metrics.py`, `evals/fictional/docs/*.md` (the 6 week-1 docs copied, plus 6 new Brightwater docs), `evals/fictional/questions.jsonl`
- Test: `tests/week02/test_dataset.py`, `tests/week02/test_metrics.py`

**Interfaces (Produces):**
- `@dataclass GoldSpan(source: str, quote: str | None = None)`. `source` matches a `Document` whose `source` equals it or whose file name equals it. `quote=None` means the whole document is relevant (BEIR document labels).
- `@dataclass EvalQuestion(id: str, question: str, answerable: bool, gold: list[GoldSpan], reference: str | None = None, tags: list[str] = [])`
- `load_questions(path) -> list[EvalQuestion]` reads JSONL with keys `id, question, answerable, reference, gold:[{source, quote}], tags`.
- `@dataclass Located(source: str, start: int, end: int)`. A whole-document match gives `start=0, end=len(text)`.
- `class GoldNotFoundError(ValueError)`.
- `resolve_gold(questions, docs) -> dict[str, list[Located]]` maps each question id to its gold spans. The quote is matched as a regex of its words joined by `\s+`. Any miss raises `GoldNotFoundError` naming the id, source and quote.
- `chunk_gold(chunk: Chunk, gold: list[Located]) -> set[int]` gives the indices of the gold spans the chunk overlaps (same source and `chunk.start < g.end and g.start < chunk.end`).
- `collapse_to_documents(hits: list[Hit]) -> list[Hit]` keeps the first hit per source, in order.
- `retrieval_metrics(hit_gold: list[set[int]], n_gold: int, ks: tuple[int, ...]) -> dict[str, float]` returns `recall@k` and `ndcg@k` for each k, plus `mrr`. A hit's gain is 1 only if it covers a gold index no earlier hit covered, so duplicates add nothing. IDCG = `min(n_gold, k)` ones. MRR = 1/rank of the first hit covering any gold, else 0.
- `mean(xs) -> float | None` ignores `None`. `percentile(xs, p) -> float | None` (linear, like numpy).

- [ ] Step 1: Tests for the metrics with hand-computed values. `hit_gold=[set(), {0}, {0}, {1}]`, `n_gold=2`, `ks=(1,3)` gives `recall@1=0`, `recall@3=0.5`, `mrr=0.5`, `ndcg@3≈0.3869`. A perfect ranking gives all 1.0. No hits gives all 0. Also `test_percentile_matches_numpy` and `test_collapse_to_documents`. Tests for the dataset: `test_load_questions_roundtrip`, `test_resolve_gold_finds_span` (`doc.text[s:e]` == the quote), `test_resolve_gold_tolerates_whitespace`, `test_resolve_gold_missing_quote_names_question`, `test_resolve_gold_whole_document`, `test_chunk_gold_overlap_rules` (touching end-to-start is not an overlap). Plus `test_fictional_questions_resolve`: loads the real `evals/fictional` files and asserts every gold quote resolves, there are ≥ 36 questions, ≥ 6 are unanswerable, unanswerable ones have empty gold and a null reference, and ids are unique.

### Task 3: The judge and refusal detection

**Files:**
- Create: `raggy/evals/judge.py`
- Test: `tests/week02/test_judge.py`

**Interfaces (Produces):**
- `JUDGE_VERSION = "judge-v1"`.
- `is_refusal(text: str) -> bool` is true when `NOT_FOUND` appears in the text, after normalising curly apostrophes and case. Ollama sometimes adds prose before the sentence, and that still counts as a refusal.
- `parse_json_object(text: str) -> dict` takes the first balanced `{…}` (a code fence is fine). It raises `ValueError` if there is none.
- `@dataclass Verdict(correctness: float | None = None, faithful: bool | None = None, citation_precision: float | None = None, reason: str = "", error: str | None = None)`
- `class Judge(llm: LLM)`, with `.name` = `llm.name` and `.judge(q: EvalQuestion, answer: Answer) -> Verdict`. It makes two calls. (1) Correctness: question, reference and answer go in; `{"verdict": "correct"|"partial"|"incorrect", "reason": str}` comes back, scored 1 / 0.5 / 0. (2) Grounding: the numbered sources and the answer go in; `{"faithful": bool, "citations": [{"n": int, "supported": bool}]}` comes back. Citation precision = the supported fraction of `answer.citations` numbers (None when the answer has no citations; numbers the judge doesn't mention count as unsupported). Either call failing (`LLMError` or a parse error) sets `error` and leaves the scores of the failed part as None.
- The prompts are module constants (`CORRECTNESS_SYSTEM`, `GROUNDING_SYSTEM`). They are strict: judge only against the reference or the sources, paraphrase is fine, a missing key fact is "partial", and any added fact contradicting the reference is "incorrect".

- [ ] Step 1: Tests: `test_is_refusal_variants` (exact text, prose then the sentence, curly apostrophe, normal answer → False); `test_parse_json_plain`, `test_parse_json_in_fence`, `test_parse_json_none_raises`; `test_judge_scores_correct_and_citations` (FakeLLM with a callable reply chosen by system prompt: correct, plus citations [1 ok, 2 bad] → precision 0.5); `test_judge_missing_citation_counts_unsupported`; `test_judge_garbage_records_error`; `test_judge_llm_error_records_error`.
- [ ] Step 2: Implement. Tests pass. Commit `feat(week2): LLM judge (versioned prompts) and refusal detection`.

**Files:**

**Interfaces (Produces):**
- `@dataclass Suite(name: str, documents: Callable[[], list[Document]], questions: Callable[[], list[EvalQuestion]], fingerprint: Callable[[], str], ks: tuple[int, ...], unit: str, answers: bool)`. `unit` is `"chunk"` or `"document"`.
- `fictional_suite(root=Path("evals/fictional")) -> Suite` uses `ks=(1, 4, 10)`, unit chunk, answers True. Its fingerprint is the sha256 over sorted (name, bytes) of the docs and the questions file.
- `load_beir(dir: Path, split="test") -> tuple[list[Document], list[EvalQuestion]]`. Documents get `source=f"scifact:{_id}"` and `text = title + "\n\n" + text`. Only queries with qrels score > 0 are kept, with `answerable=True`, `tags=["scifact"]` and gold = `GoldSpan(source)` per relevant document.
- `download_scifact(data_dir: Path, url=SCIFACT_URL, sha256=SCIFACT_SHA256) -> Path`. It downloads to a `.part` file, verifies, extracts into a temp dir, then renames it to `data_dir/scifact`. When the folder exists it skips. A mismatch raises `DatasetError` with the URL and the expected and actual hashes, and deletes the `.part` file.
- `scifact_suite(data_dir=Path("evals/data")) -> Suite` uses `ks=(1, 10, 100)`, unit document, answers False. Its fingerprint is the zip sha256.
- `SUITES: dict[str, Callable[[], Suite]]`.
- `prepare_index(suite, raggy) -> dict`. The index lives in `raggy.config.index_dir`. The stored `key.json` holds {fingerprint, embedder, chunk_size, chunk_overlap}. If the key matches, it returns `{"cached": True, …}`. Otherwise it deletes the folder, runs `ingest_documents` and returns `{"cached": False, "documents", "chunks", "seconds"}`.
- `run_suite(suite, raggy, judge: Judge | None, *, answers: bool = True, limit: int | None = None, label: str = "", progress: Callable[[int, int], None] | None = None) -> dict`. It retrieves `max(ks)` units. For document units it searches `3 × max(ks)` chunks and collapses. Retrieval metrics cover answerable questions only. When `answers and suite.answers`, the context is the first `config.top_k` chunk hits, passed to `generate_answer`. Unanswerable questions skip the judge. Refused answerable questions get correctness 0 and no grounding call. Each question records `latency_ms: {retrieve, generate}`. The run record is {`schema: 1`, `suite`, `label`, `created` (ISO), `git_commit`, `config` (embed model, chunk size and overlap, top_k, llm name or None, judge name or None, `judge_version`), `ingest`, `metrics`, `by_tag`, `counts` {questions, answerable, unanswerable, errors, judge_errors}, `questions`: [ … ]}. `metrics` holds the averages of each retrieval metric, `correctness`, `faithfulness`, `citation_precision`, `refusal_accuracy` (over all questions: unanswerable → refused, answerable → not), `unanswerable_refused`, `answerable_refused`, and `retrieve_ms_p50/p95` and `generate_ms_p50/p95`.
- `save_run(run, out_dir) -> Path` writes `out_dir/<suite>/<YYYYmmdd-HHMMSS>[-label].json`. `load_run(path) -> dict`.
- `format_run(run) -> str` gives a metrics table plus per-tag recall@k and correctness, and lists errored questions. `format_compare(base, new) -> str` gives base, new and delta per shared metric, with a `+`/`-` sign.
- CLI: `raggy eval [--suite fictional|scifact] [--retrieval-only] [--no-judge] [--limit N] [--label TEXT] [--out evals/runs]` prints the table and the saved path. The eval index lives at `config.index_dir / "evals" / suite`. `raggy compare BASE.json NEW.json`. A `DatasetError` gives a one-line error and exit 1.
